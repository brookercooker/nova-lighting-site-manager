# Design Chat (src/pages/admin/designChat) rules
- Review resolution first asks the synchronized visible frame with exact origin/window/path checks, then offscreen fallback. Adopt inventory fp only when stored fp is absent, never overwrite it for disagreement; dev diagnostics log field names/booleans/counts only. Pre-existing saved/preview skew offers neutral Manual fallback; only optimistic save conflicts describe changes during editing.
- Missing internal destinations never permit Looks right or resolve through legacy Keep decisions; Edit remains primary. Unnamed links identify their source page; preview credentials stay only in opening hrefs, stripped from display/saves. Phone controls retain 44px targets/reachable actions; status summaries stay compact without rewriting history.
- The top bar starts with Preview/Objects/Images/Videos; one review-variant Submit stays hidden during manual editing. Submit always opens SubmitConfirmDialog (bulleted explanation: automatic review first, a developer for anything it cannot approve, approved changes go to the public site; plus a plain bulleted checklist, nothing to tick) before /publish; hosts that unmount their opener (phone overflow) pass onRequestSubmit and render the dialog themselves. At phone widths Capture is the stretched primary top-bar button, and Edit/Done Editing, Submit and Account/Pages/Status/Help use the labelled top-bar overflow; otherwise the left-header rail is Account, Tools (Capture, Status), Pages, Help.
- The page chip (WorkingPageChip) sits just below the Chat/Manual Edit mode switch on tablet/desktop in both modes: "Editing" in Manual, "Working on" a picked page (clearable), else "Viewing" the preview page. Phones keep it in the chat composer. Selected library references show a "Selected (N) · Sent with your next message" heading. User-facing text never names Claude as the one making changes; the chat service is "the builder" (Chat Mode announcement, busy notices, Change It in Chat buttons).
- Left-header actions consume DesignChatContext and reuse SubmitButton/ReviewProblems; Tools > Status (StatusMenuItem) toggles ReviewChangesView in place of the chat (chat hidden, never unmounted), listing only relay draft.requests (count from publish.open, count-only when requests are absent); chat history must never be presented as a change ledger, and full-session discard must never masquerade as single-change undo.
- Wait indicators share waitEstimates and a provider relay tracker with monotonic stages/server time; finish on post-reply build timestamp or confirmed new frame. Preview notifications still require the build frame to load; only finished no-change jobs with an unchanged preview version and no checking/build dismiss their card after a 10-second grace without a completion notice, so late commits retain the real build flow. Retain old frames/polling. Save progress observes the existing contentSync queue through draft acceptance.
- Blocked reviews show people only "These changes need to be reviewed by a developer." (problemsModel, no finding list, no fix buttons); "Fix this for me" and per-finding details (FindingsList, developerFindings) appear only for admin accounts inside the Changes Waiting for Review view, never in the chat or for other people.
- Admins reject via POST /reject with a 3–300-character reason; show undo/kept counts and validated decision reasons; Manual edits stay.
- Walkthrough approvals/opened/kept/replaced maps persist in versioned tab sessionStorage keyed by page/link plus fingerprint, reconciled only against ready draft data and cleared on reset; transient dialogs/editor/final checklist never persist. Link states remain Needs Checking, Confirmed and Replaced by Hand; strip legacy linkWrong safely.
- The preview link-check bridge (LinkCheckBridge, mounted only while a page is checked in the visible Chat preview) speaks protocol v2: it sends every changed link (page and shared-piece groups, max 100) as {raw,state} and resends on any change; trusted v2 clicks select/scroll/focus the matched inline review row and reopen the phone review panel. Request interceptAll:true; unmatched match:null clicks show a sidebar note. Public must suppress all review link navigation; never access cross-origin DOM.
- Chat error lines normalize string/numeric relay IDs through idKey, merge legacy storage with memory up to 200 and transfer pending anonymous dismissals when identity resolves; id-less keys use only stable timestamp/text. Dismissals across chat/review/wait/composer are presentation only and never feed busy/blocked/Submit; admin-only ErrorDetails mounts solely for has-role admins on hasDetail lines.
- Walkthrough auto-open consumes walk.open's autoOpen once after pagesStatus ok on all widths; phone openPage collapses the sheet and exposes Back to Review, preserving viewed/approval state. Never repeat on reopen/refresh/already-checking. Page tab links retain target=_blank and noopener noreferrer. Show on Page uses the existing readiness/focus path. linkText prefers short own/aria wording, extracts short trailing uppercase actions from whole-card labels or truncates at 50 characters; blank/address labels use friendly page names, and inline rows share that formatter.
- Link verification lives only on the Verify Changed Links step: rows offer Show on Page (openPage as kind "link" on the group page, else first changed page, else "/", then focusWhenReady) and Open Link to Verify plus Looks right (walk.confirmLink stores approval; fingerprinted verificationOpened gates web checkboxes). Design Check Approve needs only viewed; PAGE_SUGGESTIONS are plain bullets there and in the Checking Changes bar. LinkCheckBridge mounts only via linkCheckActive (step "links" + (checking or open) + visible, not editing).
- Correct opens ReviewLinkEditor inline on all widths; propagate stored override/inventory elementKey+scope through rows and saved replacements. reviewLinkSave matches that identity first, never label-falls-back when it exists; without identity use unambiguous href/label only. Known target/fingerprint and conflict-checked saveRow remain mandatory. Failure shows a neutral explanation, primary Manual action and no dead Save. Saves clear old/new gates and preserve other approvals through repin; replaced rows omit frame checking.
- Link verification is entirely in sidebar rows, never a dialog: safe Open Link to Verify anchors set fingerprinted opening state; Looks right ticks/un-ticks approval, web links wait for opening, mail/tel remain immediate. Missing pages always block with Edit primary, including legacy Keep decisions. Selected row rings and focuses the verify action; phone review reopens via existing walk.open handling. Compact actions retain 44px phone targets; final Submit unchanged.
- Verify Changed Links step rows = relay review-links merged (mergeReviewLinks) with link:<path> overrides on hand-edited pages, friendly page names, refetched on CONTENT_SAVED; when VITE_PUBLIC_LIVE_URL is set and frames answer link-inventory v1 (linkInventory.ts, 3 s timeout, first page probes), each changed page's group is replaced by its draft-vs-live diff, else the merged list stays. Change This Link waits for FramedPageEditor readiness (after edit-init, exposed by data-edit-ready), retries edit-select-link every 500 ms for six seconds and trusts only exact frame window/origin/href replies; false replies never end retries, late success clears the hint, and count reports multiple matches without inventing a scope hint. The card-link hint shows only without selection.link (linkKnown).
- Review link decisions use only their own href, target and stored key/scope fingerprint, never group/page/request revisions or link repinning, so unrelated saves cannot clear or silently renew approval.

- Review link-click listeners register before enabling interception and accept validated v2 clicks without a ready-message gate; explicit match:null opens the unchanged note, while safe dev diagnostics redact credentials. Status and All Changes share reviewLog: use a validated complete published-baseline inventory when supplied, otherwise retain relay pending counts; save descriptions never establish live-baseline equivalence.

- Step 2 cards activate preview focus via click/Enter/Space, including closing phone review on repeated selection; inner actions/editors never bubble. Top-right 44px safe verification icons precede 44px Approve toggles and Correct. Restore deletes only the link override; Remove writes unlinked:true with the existing fingerprint/conflict guard, never hidden or element deletion.
- Verify Changed Links tiles show reported linked wording or Image, destination only and actual missing-page/risk context; neutral surfaces have only a small selected indicator. Approve/Correct keep equal tracks and fingerprinted opening gates; optional inventory display fields never authorize writes.
- Review removal requires a named confirmation and an available original destination; keep the editor open and re-read the removed override/version before restoration to preserve conflict checks. Card or preview-row selection discards the local editor so it cannot remain attached to a different selection.
- Shared review links merge registry overrides and inventory by object scope/element key into one usage-labelled group; safe resolution writes that registry row, never a page copy. Page approvals ignore fp/orig metadata and lifecycle timestamps but retain actual page/shared content and committed request identity.
- Shared usage lists are collapsed counts with bounded expansion; changed chrome gets one Design Check row. Only proven hand-edit restores may drop empty shared overrides; no local published-baseline guesses. Stored identity resolves before href filtering, with authoritative visible wording retained after saves.
- Review focus sends immediately on exact-window/origin target location, then retries on trusted link-check-ready in the background; a small nonblocking cue and one automatic navigation retry never report failure solely for a slow handshake.
- Verify Changed Links risk rules are presentation-only in linkRisk.ts (tldts registrable domains); freeze ordering on step opening/destination changes and persist group preferences separately from approvals so confirmations never reorder rows. Trusted domains belong to this site’s isolated database with admin-role RLS and validated hosts, never visitor storage.

- Compact review controls mount in the preview independent of sidebar openness; keep the review navigation row hidden while checking to preserve canvas space. Log grouping is presentation-only; full edit/author details expand on demand and pagination starts at ten.
- Review inventory display caches are origin/path-scoped in the query client; wait for metadata requests before ready, retain same-identity/destination facts across failures and never use cached display facts as write authority. Risk summaries expose one strongest reason with details; editor host warnings share the row rules without changing save/approval gates. Peeks resolve saved images/thumbnails through signedThumb and never infer publication from page lifecycle status.

- Review row ids use reviewLinkIdentity (page path + inventory scope/position, object scope/position globally; repeated keys add inventory index), never destination/label aliases; net and session merges preserve only same-identity metadata. Published originalHref wins over replay metadata; risk context retains inventory partners without adding review rows. Approval invalidation warnings require an actual changed approval record. Legacy removed/handled rows retain Review Again and full actions. Trusted-domain storage/data is retained but no review UI or approval path consumes it.

- During a walkthrough, hide pickers/Capture/opening Submit; Return to Edit exists only in the desktop Submit slot or phone Menu. Status opens the retained change ledger in a dialog without mutating walkthrough state. Design Check uses an inert frame plus DesignCheckShield pointer/touch/keyboard scrolling through the existing exact-origin restore-scroll protocol, so visitor controls cannot navigate. Approve advances, Next Page skips, and final-page approval returns to the list; four final attestations are manual and never derived from page/link progress.
- Design Check reminder follows its title above the list; checking-bar approval/skip controls share compact 44px geometry, with one quiet Approved state on the existing advancing control, so styling never changes navigation or approvals.

- Keep the walkthrough mounted while phone page checking hides it; walkthrough queries disable window-focus/reconnect refetch so safe new-tab verification returns without list flash or scroll reset. Correct preserves target/write safeguards, exposes only destination/testing/Save/Cancel plus secondary safe Restore/Remove; verification tabs are never auto-closed.

- Review hides the page navigation/options bar entirely; PreviewTools exposes 44px full-screen and safe new-tab icons beside device settings, sharing existing toggleFull and current-page URL semantics. Design Check alone applies inert/shield; Verify Changed Links removes both and uses exact-frame v2 interception to select changed rows or note unchanged links without navigation. Reminder lead-in spacing stays fixed while bullets use 4px gaps and normal line height.
