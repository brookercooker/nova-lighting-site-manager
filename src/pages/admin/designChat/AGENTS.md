# Design Chat (src/pages/admin/designChat) rules
- The top bar starts with Preview/Objects/Images/Videos; one review-variant Submit stays hidden during manual editing. Submit always opens SubmitConfirmDialog (bulleted explanation: automatic review first, a developer for anything it cannot approve, approved changes go to the public site; plus a plain bulleted checklist, nothing to tick) before /publish; hosts that unmount their opener (phone overflow) pass onRequestSubmit and render the dialog themselves. At phone widths Capture is the stretched primary top-bar button, and Edit/Done Editing, Submit and Account/Pages/Status/Help use the labelled top-bar overflow; otherwise the left-header rail is Account, Tools (Capture, Status), Pages, Help.
- The page chip (WorkingPageChip) sits just below the Chat/Manual Edit mode switch on tablet/desktop in both modes: "Editing" in Manual, "Working on" a picked page (clearable), else "Viewing" the preview page. Phones keep it in the chat composer. Selected library references show a "Selected (N) · Sent with your next message" heading. User-facing text never names Claude as the one making changes; the chat service is "the builder" (Chat Mode announcement, busy notices, Change It in Chat buttons).
- Left-header actions consume DesignChatContext and reuse SubmitButton/ReviewProblems; Tools > Status (StatusMenuItem) toggles ReviewChangesView in place of the chat (chat hidden, never unmounted), listing only relay draft.requests (count from publish.open, count-only when requests are absent); chat history must never be presented as a change ledger, and full-session discard must never masquerade as single-change undo.
- Wait indicators share waitEstimates and a provider relay tracker with monotonic stages/server time; finish on post-reply build timestamp or confirmed new frame. Preview notifications still require the build frame to load; only finished no-change jobs with an unchanged preview version and no checking/build dismiss their card after a 10-second grace without a completion notice, so late commits retain the real build flow. Retain old frames/polling. Save progress observes the existing contentSync queue through draft acceptance.
- Blocked reviews show people only "These changes need to be reviewed by a developer." (problemsModel, no finding list, no fix buttons); "Fix this for me" and per-finding details (FindingsList, developerFindings) appear only for admin accounts inside the Changes Waiting for Review view, never in the chat or for other people.
- Admins reject via POST /reject with a 3–300-character reason; show undo/kept counts and validated decision reasons; Manual edits stay.
- Walkthrough per-page checks live in the walk store keyed by page key plus page fingerprint (reset on change); link confirmations from Check This Link reuse linkTicked/linkApprovals with the `${page.path}|${raw href}` key, and "This Isn't Right" marks hold until the link fingerprint changes — one source of truth for the Links step and final checklist.
- The preview link-check bridge (LinkCheckBridge, mounted only while a page is checked in the visible Chat preview) speaks protocol v2: it sends every changed link (page and shared-piece groups, max 100) as {raw,state} and resends on any change; clicks open Check This Link only after a v2 link-check-ready and only when `match` is a listed raw. v1/no reply leaves links untouched; per-line Check This Link buttons always work.
- Chat error lines: per-person dismissals (chatErrors.tsx, localStorage by history id capped at 200, id-less lines session-only) are presentation only and never feed busy/blocked/Submit; admin-only Show Details mounts ErrorDetails solely for has-role admins on hasDetail lines, so /api/admin/error-details is never called for others.
- Walkthrough auto-open: walk.open sets autoOpen, consumed once (any checking set clears it) to open the first row with a page via openPage after pagesStatus ok — never on phones, after Back to Review/reopen, or on refresh. Show on Page on an unchecked row runs openPage then focusWhenReady (v2 link-check-ready or timeout). Unlabelled links display linkText ("Link to <page name>" for known internal pages, else the address).
- Link verification lives only on the Links step: rows offer Show on Page (openPage as kind "link" on the group page, else first changed page, else "/", then focusWhenReady) and Check This Link (walk.confirmLink is the approval; no linkOpened gating). Pages-step Approve needs only viewed; PAGE_SUGGESTIONS are plain bullets there and in the Checking Changes bar. LinkCheckBridge mounts only via linkCheckActive (step "links" + checking + visible, not editing).
- Change This Link (wrong links only, Links step rows and the Check This Link window) stores walk.fix and enters Manual Edit via useModeSwitch.requestManual; a successful Save Changes (finishEditing) or the banner's Back to Review returns straight to the Links step via finishFix, never to plain Chat Mode. Only a saved fix sets linkReplaced (key + ownLinkPrint) and a short repin so that page's approval and confirmed links follow the hand save; replaced counts as resolved and is omitted from the frame list. Keep Editing, cancelled entry and other Manual exits clear walk.fix.
- Check This Link never embeds a destination frame: internal/anchor new tabs reuse publicPreviewBase/publicPreviewPage with the shown draft frame address; HTTPS opens directly and mail/tel show only the address. Confirm Link/Unconfirm use walk.confirmLink and close immediately, without opening gates; missing-page warnings never disable confirmation. Dialog actions stack at 44px so phones stay within the viewport.
- Links step rows = relay review-links merged (mergeReviewLinks) with link:<path> overrides on hand-edited pages, friendly page names, refetched on CONTENT_SAVED; when VITE_PUBLIC_LIVE_URL is set and frames answer link-inventory v1 (linkInventory.ts, 3 s timeout, first page probes), each changed page's group is replaced by its draft-vs-live diff, else the merged list stays. Change This Link waits for FramedPageEditor readiness (after edit-init, exposed by data-edit-ready), retries edit-select-link every 500 ms for six seconds and trusts only exact frame window/origin/href replies; false replies never end retries, late success clears the hint, and count reports multiple matches without inventing a scope hint. The card-link hint shows only without selection.link (linkKnown).
